# Codex協調サブエージェントへの移行

## 目的と承認済み方針

ユーザー指定: ネストした `codex exec` を独立コンテキストの協調サブエージェントに置き換え、役ごとの入力を必要文書に限定し、委譲・並列実行・独立判定を維持する。

旧ネストプローブの失敗を、直接起動や全委譲機能の失敗と一般化しない。今回の方式変更はCodex版だけに適用する。Claude版と共有テンプレート9枚は変更しない。本仕様は初期移植設計のCLI起動・隔離・再開に関する判断を置き換え、それ以外のフェーズ・Human Acceptance契約を維持する。

## 実行契約

- driverが全役を `collaboration.spawn_agent` / `fork_turns: "none"` で直接作成する。サブ役からの再委譲は禁止を既定とする。
- model/effortは既存の役割表を維持する。環境の実際のAPIと対応モデルを起動前に確認し、未対応なら理由を示して停止する。ネストCLIへ自動フォールバックしない。
- proxyは `followup_task` で往復する。judgeは判定ごとに新規作成し、proxy・builder・reviewerのagentを流用しない。
- `send_message` は稼働中の指示補足、`followup_task` は応答を必要とする追加入力。完了通知・待機・状態確認を混同しない。
- 独立した担当範囲だけ並列化する。共有ファイルの同時編集は禁止。driverが必要な全結果と検証証拠を確認してからjudgeへ提出する。builderはコミットしない。

## 入力と独立性

judge/proxyには選んだ文書本文を境界付きの入力データとして渡し、ツール呼び出し・ファイル探索を指示で禁止する。足りない資料はdriverへ要求する。builder/reviewerには必要文書に加えて対象コードの範囲を明示する。全会話・リポジトリ全体の無条件ロードは行わない。

役が必要とする否定リスト・発火条件・出力契約は、driverが役への指示として別途渡す。親のポリシー読込は継承されない。資料不足はgateの `REVISE` / `return_to: "driver:資料補完"`、escalationの `ASK_HUMAN` という有効なJSONで返す。driverが補える既存資料だけなら人間への中継前に資料を追加し、新規judgeへ再提出する。資料を補っただけで本来の業務判断を承認した扱いにはしない。

協調APIは作業ディレクトリとファイルシステムを共有する。`fork_turns: "none"` は親会話の非継承であり、OSのアクセス制御やツールの無効化ではない。一時ディレクトリへのコピーだけでもアクセス隔離は成立しない。この制限をREADME・PL-009・E2E項目に明記する。

## 判定と障害

CLIの `--output-schema` に依存せず、返されたJSONをdriverがそのまま保存し、PowerShell 7の同梱検証スクリプトを別プロセスで実行する。JSON Schemaに加え、PASSと差し戻し項目の矛盾、空の根拠、ASK_HUMANの質問欠落などを拒否する。終了コード0の場合だけ判定を採用する。パース・検証・起動・待機の失敗はPASSではない。

judgeへの同一agentの追加入力は、資料・証拠・判定基準を変えない質問意図や既回答箇所の明確化だけ1往復を許可する。不足資料を追加する場合も新規judgeで再判定する。形式不正の回答はdriverが修正せず、新規judgeに1回だけ再依頼し、再び無効なら停止する。

## 永続化と移行

`state.md` に `execution-backend: collaboration`、`proxy-agent`、`skill-dir` を保存する。CLI由来の `proxy-session` / `codex-path` は履歴として扱い、agent IDに変換しない。旧状態・セッション跨ぎ・agent消失時はgoal-seed/frame/hearing-log等から新規proxyを作る。判定結果と人間承認は保存文書を原本とする。

call-logは既存の時刻・役・フェーズ・目的の4列を維持し、agent ID、model/effort、入力・出力参照、結果を追加する。失敗・補足往復も記録する。

## 受け入れ基準

1. 現行の起動手順にネストCLI成功を要求しない。
2. 必要文書だけのproxyへの初回委譲と追加入力、新規judgeの独立判定が機能する。
3. 不正JSON・不整合な判定は検証スクリプトが非ゼロ終了する。
4. 並列・再開・消失・旧状態の取り扱いが本文とREADMEで一致する。
5. 既存テンプレート一致検証を通過する。E2E未実施部分を検証済みとしない。
