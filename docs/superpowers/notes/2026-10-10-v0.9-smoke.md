## 4. 実装中に実測で分かったこと

- `powershell -File` は、単独の `-` を引数の値として渡せない(`-SetCodexRun -` で powershell.exe が出力ゼロで終了する)。`loop-log.ps1` に `-Clear 'key,key'` を足し、空文字も `-` と扱うようにした
- `powershell -File` では配列パラメータに複数値を渡せない(`-Set a b` は 2 つ目が位置パラメータに吸われ、`PositionalBinding=$false` でも不可)。欄ごとの名前付きパラメータ(`-SetPhase` …)にした
- 子 PowerShell の標準出力に日本語を含めると、Bash ツール経由では化ける(cp932 の console を UTF-8 として読む)。PowerShell ツール経由では化けない(`[Console]::OutputEncoding` が UTF-8)。`loop-log.ps1` の KV 出力は ASCII だけにした。フックの JSON は `Write-StdoutUtf8` で UTF-8 バイトを直接書くので影響しない
- 日本語の引数(`-Purpose "B-6 ゲート判定"`)は Bash / PowerShell どちらのツールから `-File` で渡しても化けない(ファイルに正しく書かれる)
- コミットの無いリポジトリで `git rev-parse HEAD` は stdout に文字列 `HEAD` を返す(空ではない)。`impl-check.ps1 -Prepare` は 40 桁の SHA かで判定する
- `scripts/sync-templates.ps1 -Mode Verify` は v0.7 以降ずっと失敗していた(`grareco-prompt.md` の Codex 側コピーが古い)。`-Mode Copy` で複写し直した

## 4-1. プラグイン更新の罠(2026-10-11)

- `claude plugin update` は版番号が変わらないと **キャッシュ `~/.claude/plugins/cache/<marketplace>/<plugin>/<version>/` を再コピーしない**。v0.9 の実装中に一度 0.9.0 を入れ、レビュー対応後に再度 update したところ「0.8.1 → 0.9.0 に更新」と表示されたのに中身は最初のコピーのまま(修正後の `cwd mismatch` 判定が無い)だった。キャッシュを消して update すると「already at the latest version」で再コピーされず、キャッシュが空のままになる
- 正しい手順: `claude plugin uninstall r-super-loop-powers@r-super-loop-powers-marketplace -s user` → `claude plugin install … -s user`。インストール後に `cmp` でリポジトリと一致することを確認した(hooks / bin / SKILL / workflow / builder すべて同一、installed_plugins.json の gitCommitSha = main)
- main を checkout すると `core.autocrlf=true` でファイルが CRLF になり、SKILL.md のバイト数が 24 KB をわずかに超えた。サイズ検査は LF に正規化して数えるよう直した(99f49d6)
