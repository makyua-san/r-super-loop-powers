## 2. spec と違う点(計画の表 P1〜P7 に無かったもの)

- **D5「両方止めて直列に戻す」**: 実装は、見立て外れに気づいた側がそのまま自分のマイルストーンを続けて 1 本だけ合流し、もう片方をベースでやり直す。計画の本文(`references/parallel.md` 5)には書いたが、冒頭の表には入れていなかった。

## 3. 確かめていないこと

- 2 つの実セッションを並べた通しの確認(README の E2E の 4 項)。テストは一時リポジトリでの機械的な検査まで。
- 新しい作業ツリーのフォルダで、Claude Code がこのプラグインとフックを読み込むか(フォルダの信頼の確認を含む)。

- サブモジュール・LFS・sparse checkout・長いパスでの `git worktree add`。

## 4. 直さずに残したもの(次の版の候補)

最終レビュー後の再レビューで出たもの:

- N1: 「ベースで未追跡のファイルをコミットしない」検査が、子が `git mv` でその場所へ動かしたファイルを見逃す(`--no-renames` が要る)。その場合は `-Merge` が `FAILED` になる。
- N2: 上の検査が候補のパスを 1 つのコマンド行に並べる。無視されていない新規ファイルが数千あると Windows の上限を超え、`STATUS:` 行なしで落ちる。
- N3: 片方だけ合流した後に `-Cleanup -Abandon` すると、合流済みの方も `parallel-log.md` に `redo` と書かれる(手順書はこの場合を `-Halt -Keep` に送っている)。
- N4: `gate-decision.md` の先頭が凡例(`PASS | REVISE | …`)だと、最初の判定語の検査を通ってしまう(以前の検査でも同じ)。
- `references/parallel.md` 2 の「ベースで起動されたら」の段落から、5 の打ち切りの項へ案内が無い。

タスクごとのレビューで軽微とされ、そのままにしたもの:

- hook-common.ps1: `milestone:` の値が空で次の行が数字で始まると、その数字を番号として読む。
- `Get-ParallelTag` の、番号で始まらない milestone・milestone 無しの直接のテストが無い。
- `-Prepare`: 子の state.md から BOM が落ちる。番号を文字列で比べるので `01-a,1-b` が通る。
- `-Pass`: コミットに失敗したとき、利用者が手でステージしていた分もステージから外れる(ファイルは変わらない)。
- `-Merge`: 衝突でない失敗は、ゴール記録のコミットや先のマージが済んだ後に `FAILED` になる(再実行は安全)。ベースの未コミット検査がパスの大文字小文字を区別する。`parallel-log.md` の追記と `group.json` の更新の間で落ちると、区画が 2 つになる。衝突したファイル名に `"` があると、`NEXT:` のコマンドがそのまま貼れない。
- `git worktree prune` はリポジトリ全体に効く。`info/attributes` に足した行は後片付けの後も残る。
- SKILL.md のフェーズ表に `parallel` の行が無い(残り 48 バイト)。パケットの 9,500 文字の上限は SKILL.md からも references からも消えた(スクリプトは従来どおり守る)。
