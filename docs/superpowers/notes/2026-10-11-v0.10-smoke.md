# v0.10 スモーク — スカウト

対象: spec §10。実施環境: Windows 11、Windows PowerShell 5.1、codex-cli 0.160.0 / `gpt-6.1-sol`(effort `low` でスパイク)。

## 1. Web 検索の設定キー(spec §10-1)

一時ディレクトリで `codex exec --json - -s read-only -c windows.sandbox=unelevated --disable plugins -m gpt-6.1-sol -c <候補>` を実行し、「npm の typescript の最新版を公式ページから答えよ。Web ツールが無ければ WEB_UNAVAILABLE」というプロンプトを渡した。`out.jsonl` の `"type":"web_search"` イベントの有無で判定した。

| 候補 | exit | 最終メッセージ | out.jsonl の web イベント | 判定 |
|---|---|---|---|---|
| (キーなし。対照) | 0 | VERSION: 7.0.2 / URL: npmjs.com | `web_search` ×4、`search` ×1 | **既定で Web 検索は有効** |
| `web_search="live"` | 0 | 同上 | `web_search` ×4 | 有効(既定と区別できない) |
| `web_search=live` | 0 | 同上 | `web_search` ×4 | 同上 |
| `tools.web_search=true` | 0 | 同上 | `web_search` ×4 | 同上(既定が有効なので効いた証拠にならない) |
| `features.web_search_request=true`(deprecated) | 0 | 同上 | `web_search` ×4 | 同上 |
| `web_search="disabled"` | 0 | VERSION: 7.0.2 / URL: npmjs.com | **なし** | **無効化できる** |

分かったこと:

- codex 0.160.0 では **Web 検索が既定で有効**。spec F19 / D77 の前提「`-Web` 無しの既定はリポジトリだけ」は、設定を渡さない限り成り立たない。
- 効いているキーは最上位の `web_search`(`"disabled"` で止まる)。有効化の明示は `web_search="live"` を使う(`cached` との差は未計測)。
- read-only サンドボックスでも Web 検索は動く(サンドボックスはシェルの制約で、組み込みの検索ツールには関係ない)。
- `web_search="disabled"` でも、モデルは `WEB_UNAVAILABLE` と言わずに記憶から `7.0.2` を答えた(effort `low`)。Web を止めても「知っている風の答え」は返り得るので、根拠の URL / `file:line` を機械的に要求する設計(D74)は正しい。scout のロール指示は「ファイルにある答えは開いて確かめる」「ファイル・行・URL を捏造しない」を保つ。

採用(D77 を実測に合わせて修正): `codex-run.ps1 -Role scout` は、`-Web` ありで `-c web_search="live"`、**`-Web` なしで `-c web_search="disabled"`** を渡す(scout だけ。他ロールには何も渡さず従来どおり)。これで「既定はリポジトリだけ」が設定で担保される。

## 2. `medium` の実力(spec §10-2)

2026-10-12。このリポジトリを `-WorkDir`、一時ディレクトリ(state.md と codex-env.json だけ)を `-GoalDir` にして `scout.ps1` を Bash ツールから呼んだ。根拠の `file:line` は全件を実ファイルと突き合わせた。

| 問い | effort | STATUS | ELAPSED_MIN | 根拠の正誤 | 累計入力トークン(うちキャッシュ) | 備考 |
|---|---|---|---|---|---|---|
| `codex-status.ps1` が `BOUNDARY_HIT` を出す条件と定義場所 | medium | OK | 0.8 | 読んだ 2 件は正(spec:28・tests:4)。本題は**未確認** | 73,886(37,376) | 実行契約 1 項が `skills/` 配下を禁じるため、codex は正しく「調査を停止」と報告した。このリポジトリは答えが `skills/` にある(ハーネス自身の dogfooding)ので、scout には答えられない問い |
| `loop-log.ps1 -Clear` の欄名はどこで決まるか | medium | OK | 0.7 | 同上(未確認) | 57,822(41,984) | 同上 |
| `hooks/context-meter.ps1` のしきい値と上書きの環境変数 | medium | OK | 0.4 | **3/3 正**(`:23` `$Threshold = 200000` / `:24` `RSLP_CTX_THRESHOLD` / `:77` `-ge $Threshold`) | 29,199(13,440) | コマンド 2 回。UNVERIFIED 0 |

分かったこと:

- `medium` で `file:line` の誤りは 0(13 件)。所要は 1 分未満。累計入力は 3〜7 万トークン(技術PM `max` の 140〜240 万と比べて 1/30 以下)。既定 effort は **`medium` のまま**(`high` の計測は不要と判断)。
- **Bash ツールから呼ぶと日本語の `CONCLUSION:` が化けた**(console code page が UTF-8 でない)。`scout.ps1` の冒頭で `[Console]::OutputEncoding` を UTF-8 にして解消(テスト `stdout-utf8-under-cp932`)。
- **ゴール文書が `-WorkDir` の外にあると codex は読まない**(実行契約 1 項「作業ディレクトリ内のみ」を守って「閲覧していない」と報告)。実運用ではゴール文書は対象プロジェクトの中にあるので起きないが、`scout.ps1` は外にあるときだけ `--add-dir` で渡すようにした(テスト `launch-add-dir-outside`)。
- 実行契約 1 項の `skills/` 禁止は、**このリポジトリ(ハーネス自身)の `skills/` 配下を問う scout には効いてしまう**。対象プロジェクトでは正しい制約なので変えない。このリポジトリで scout を使うときは `tests/`・`hooks/`・`scripts/`・`docs/` の問いに限る。
- `BOUNDARY_HIT` の WARN は、codex が実行契約を守るために書いた**除外 glob**(`--glob '!**/skills/**'` 等)にも反応する(偽陽性。5 回中 3 回)。STATUS には影響しない。パターンの改善は次版の候補(`!` 付きの glob を除く)。
